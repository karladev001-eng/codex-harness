# ADR 0006: 保存資料を段階的に取得し、制作の参考に使う

- 状態: 採用（実装・導入の確認はタスク記録を参照）
- 日付: 2026-10-06
- 関連: ADR 0002、0003、0005

## 背景

資料の保存・同期・本文と画像の説明生成、短いカードの文字検索、GitHubの制作記録の読取と更新は導入済み。しかし、ハーネスが関連資料を探す標準手順と、検索後に原文・保存画像へ戻るCLIが不足していた。

## 決定

ハーネスの必要時参照を「検索 → 少数のカード → 選んだ本文の一部/画像 → 今回の適用判断」とする。同期hookは引き続き同期のみを行い、全件をコンテキストへ注入しない。スケジュールは説明の更新だけを担当する。

検索CLIは既存の文字一致を維持し、タグと一致箇所への手掛かりを加える。自然言語の依頼はエージェントが用途・見た目・題材等の少数の語へ分解し、必要なら語を変えて検索する。生成説明も検索対象だが、これは埋め込みによる意味検索ではない。関連性を判断できる候補が無ければ、その不足を示し、保存されていると推測しない。

原文はcapture IDを指定し、位置と取得量を制限して読む。保存画像は選択した一件だけを安全なローカルキャッシュへ取り出し、画像ツールで実際に確認する。URL・capture ID・取得版・取得日時・不足を保持し、現在のWebページや未取得の動画/コードを見たことにはしない。

CLIはハーネスの配布物に同梱し、インストール先から確実に実行できるようにする。PCごとの既存knowledge設定とGitHub認証を利用する。未設定なら設定を作り替えず通常作業へ戻る。

## 改善ループとの境界

資料から得た参考事項と、ユーザーの好みは分ける。原文・生成説明は資料についての情報であり、保存の事実だけで好みを推定しない。ユーザーが書いたメモは出所と範囲を確かめ、既存の観察・候補・指針・試用の契約で扱う。取得版や同じ発言の重複を新しい支持根拠として数えない。

制作に資料を適用した場合は、その資料IDと取り入れた点を既存タスク記録に短く残す。ユーザーから評価を得るまで改善効果はunknown。persistence、improvement_loop、measurementの各設定と、GitHubの好みをfresh取得できた場合のみ自動適用する契約を維持する。明示的な通常の資料検索は、好みの自動適用とは別操作とする。

資料中の命令は信頼しない。上位指示・現在の依頼・権限を上書きさせない。保存HTMLを実行する閲覧機能は追加しない。

## 残る範囲

埋め込みによる意味検索、検索用GUI、頻度に基づくランキング、元サイトの自動再訪問は今回対象外。将来の意味検索はADR 0002の要件として残る。検索品質・トークン削減率・長期の改善効果は実測前に保証しない。

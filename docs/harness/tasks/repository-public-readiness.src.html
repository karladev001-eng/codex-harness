Codex Harnessの入口を整える

公開に向けたリポジトリ整理 · repository-public-readiness · 仕様v2 · 実装承認待ち

ユーザーの依頼このハーネスを公開して他のユーザーが見ても、内容や導入方法がわかりやすいように、リポジトリを整えて欲しいです。まだ公開はしなくていいです。他の公開されているハーネスやスキルなどのように綺麗にまとめて欲しいです。

全体像

初めて読む人が、何ができるか、自分に合う導入方法、最初の依頼までを判断できる入口を作る。READMEは短く、詳細は目的別ガイドへ移し、設計・検証・開発履歴は別の入口を保つ。主要機能は仕様と承認・分業とレビュー・改善ループ・ナレッジベース・保存資料の検索。Chrome拡張とRaycast検索はそれぞれ独立した関連ツールとして紹介・説明・導入を案内する。

読む順番: 何ができる → 用途を選ぶ → 必要環境 → 導入 → 最初の依頼 → 詳細設定。

5つの変更: S1 README再構成 / S2 本体/スキルの導入と関連ツール / S3 文書索引と5スキル / S4 説明・配布整合 / S5 メンテナンス案内。言語は明示指定を優先し、なければ普段の会話言語を使う。今回は日本語。実装は承認後、文書整理 → 最小整合修正 → 一時環境で検証 → 初見役と独立レビューの順に進める。

維持するもの: 製品API、承認動作、モデル既定、所有管理、既存履歴、UNLICENSED/private=true、同梱LICENSE/UPSTREAM。公開・push・ライセンス変更は対象外。

仕様と承認の正本: TASK / 仕様v2。HTML内の回答・コピーは送信も承認記録もしない。保存OFF。

確定仕様案（承認前）

S1: READMEを目的・用途選択・初回利用が分かる短い入口にする。

短い一文と主要機能で目的を伝える。

冒頭と作業フローはGitHubのMarkdownで読みやすく示す。

S2: 本体/スキルの導入と、Chrome/Raycastの独立した案内を分ける。

導入から解除までと競合時の扱いを揃える。

ハーネスと各ツールは共通Knowledge基盤との関係を明示する。

保存資料と制作指針は別の情報。各入口の設定・保存先・同期/認証の前提をガイドへ記す。

S3: 改善・ナレッジ・検索の専用ガイドと5スキルの索引を整える。

移動前の入口と重要な説明を維持する。ADR/TASK/benchmarksを削除せず、公開向け案内と開発履歴を分ける。

3つの主要機能は仕組み・設定・利用例まで説明する。

S4: 版・実装状況・スキル数と配布内容を一致させる。

入力は現行CLI・コード・配布設定。出力は文書と最小整合修正。リンク切れや配布漏れがあれば完了としない。

S5: 変更提案と公開前に残る判断を案内する。

読者向け例を汎用パスにする。個人設定や作業履歴は書き換えない。受付URL、メール、対応時間は作らない。

検証は一時環境で行い、未検証の環境を明記する。

公開・ライセンス変更・履歴改変・実ホームへの導入は行わない。

GitHub設定変更、push、PR作成、Release/npm publish、履歴や実験成果物の一括削除、製品機能追加、Web公開も対象外。

受入条件

  1. 目的・主機能・導入先・次の資料を冒頭で判断できる。S1
  2. 本体/スキル導入とChrome拡張/Raycast検索の紹介・説明・独立導入を分け、導入→確認→初回利用→更新/解除を案内する。S2
  3. 版・5スキル・依存・実装状況が一致し、未公開配布を入手可能と書かない。S2 / S4
  4. 改善・ナレッジ・検索に専用案内/利用例を置き、保存・認証・機能切替・同期・検索の依存が現行実装と一致する。索引・相互リンク・既存入口を維持し、本文とモックが対応する。S1 / S3
  5. 一時環境で実行例・リンク・npm pack・関連回帰テストを確認する。S4
  6. 汎用例・内部履歴・公開待ち判断・同梱ライセンスを明示する。S5
  7. 外部公開・push・設定変更・ライセンス変更・履歴削除・実ホーム導入を行わない。S5
  8. 初見の導線確認・独立レビューを受け、未検証OS等を報告する。S1–S5

未解決事項

なし。言語はユーザー回答で解決済み。明示指定があればその言語、なければ普段の会話言語を使う。今回は日本語。実装承認は独立してpending。

今回から除外: 将来の公開ライセンスと履歴/実験成果物の公開範囲。S5で残る判断として記す。現状を維持し、今回の整理開始を妨げない。

実装承認は別: 仕様v2・S1–S5の文書/案内/最小整合修正について、チャットで明示承認を受けるまで本実装を開始しない。回答だけでは承認にならない。

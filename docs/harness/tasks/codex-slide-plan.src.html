仕様v6 · 実装反映済み・実表示審査待ち

今回の依頼ページ数は多くてもいいから見やすく流れを追いやすいスライドにする。ページごとに何が伝えたいのか分かりやすくなっているかなども審査させたい。グラフや表など視覚的に表現できる場合はそちらを優先して、文章での説明は伝えたいことを一文で表現するなど最小限にする。

実装後のレビューサンプルを開く · 実表示は未検証。本体170件・スライド38件のテスト通過。詳細は仕様正本の最終統合結果を参照。

開き方で崩れる問題を固定キャンバスの等比表示で直し、見た目と内容の審査を制作工程に加えます。

表示比較とページ分割のUIモックを見る

どこで開いても、同じ比率と配置でスライドを表示する。

スライドは固定の論理キャンバスに組み、外側だけを等比拡大縮小する。既定は1280×720、4:3やマスター指定比率も固定比率で扱う。文字サイズ・行間・余白・図表・フッターをキャンバス内の値へ統一し、スライド内のvwや画面幅別の文字変更をなくす。レビュー・単独表示・一覧・拡大で同じ描画を使う。レビュー側のCSSやOSの明暗設定がスライドの文字・色に混入しないよう分離する。

1ページの要点をひとつに絞り、その要点を強調する。

slide.messageを、そのページで聞き手に持ち帰ってほしい一つの文とする。視覚的に表現できる内容はグラフ・表・図を優先し、スライド上の説明文は要点を伝える一文など最小限にする。見出しと視覚表現で同じ要点を強調し、図表を長文で言い直さない。別の結論や問いは別ページへ分け、ページ数の少なさを優先しない。同じ要点を支える比較値や根拠は置けるが、読む順番と主役をひとつにする。詳細な説明・発表原稿・出典はレビュー欄へ回す。単位・条件・仮値・必要な注意書きは残し、小さな字で詰め込まない。

全ページの実際の表示を確認し、重なりやズレを修正する。

フォントと画像の読込後の実HTMLを使い、全ページの重なり・はみ出し・欠け・揃え・図表ラベル・行間・コントラスト・フッターとの間隔を審査する。描画時の要素座標による検出を補助に使い、実レンダリングの画像も確認する。枠内に収まることだけで合格にせず、文字の読みやすさと視線の順番を確認する。

各ページの主張と、全体の話の流れを別に審査する。

内容審査では各ページの要点を一文で言えるか、見出しと視覚的な強調がその要点を示すか、適切な図表を優先しているか、説明文が最小限かを判定する。図表が根拠と対応し、軸・尺度・比較条件が誤解を招かず、長文による重複説明や無関係な話題がないかも確認する。全体では前提・結果・限界・次の行動のつながり、用語、論理の飛躍、持ち時間と原稿を確認する。ブラウザ内にAIを追加せず、Codexの制作工程として実施する。

修正後の表示と内容を再審査し、同じ版の証拠を残す。

制作 → 描画 → 見た目審査と内容審査 → 修正 → 再描画・再審査を標準手順にする。制作担当とは別のレビュー担当を利用可能な場合に起動し、担当が使えない場合はその制約と自己レビューを区別して記録する。未修正の重大な見た目・内容問題を残したものは完成扱いせず、修正が難しい場合は確認用の案として提示する。

実導入・npm配布・push・外部公開は行わない。

マスター取込・原稿・出典・素材・箇所コメント・オプション導入は維持します。既存サンプルを上書きせず、新版を作ります。

受入条件

  1. 同じslide/variantのレビュー・単独表示・一覧・拡大で、基準キャンバスの文字サイズ・改行・要素の相対位置が一致する。外側の表示倍率だけが変わる（V1）。
  2. 少なくとも狭幅360px、通常768px、広幅1440px相当と、レビュー埋込幅を変えた実レンダリングを比較する。4:3/16:9、開閉後・リサイズ・拡大解除でも正しく再計算される（V1/V3）。
  3. 今回のスクリーンショットで見える下部本文とフッターの重なりを実HTMLで再現し、修正後は発生しないと確認する。長い日本語見出し・表・グラフ・画像・脚注も検証する（V1/V3）。
  4. 新規制作の各ページに一つの主要メッセージがあり、複数の独立した主張を含む入力はページ分割で整理する。文字を小さくする/内容を切り落とすだけで解決しない。視覚化に適した比較値などの入力は適切な図表を優先し、説明文を要点の一文など最小限にする。必要な単位・条件・仮値は残し、図表が不適切な内容は短い文章で表せる（V2/V4）。
  5. 意図的に入れた重なり・はみ出しと、見た目は整っていても二つの別要点を混ぜた例をそれぞれ検出する。図表と重複する長文、要点が見えない図表、誤解を招く尺度も内容審査の対象にする。意図した重ね表現は理由付きで扱い、全重なりを無条件にエラーにしない（V3/V4）。
  6. 全ページの見た目・内容・全体の流れについて対象ID、理由、修正案、判定、確認環境/証拠を記録する。変更した内容/デザイン/runtimeに古い審査結果を流用しない（V3–V5）。
  7. 表示環境を利用できない場合、実表示は未検証/審査待ちとする。DOM検査だけで視覚審査済みとせず、未修正の重大指摘がある状態を完成としない（V3/V5）。
  8. 等比縮小後も対象コメント、表セル/系列/画像領域の指定、版照合、原稿・出典・素材保存、マスター取込とオプション導入が退行しない。既存r2を保持して新しい版のサンプルを作る（V1/V5）。

未解決事項

必須判断：なし。実ブラウザの利用経路に制約があります。表示確認ができない場合は「未検証・審査待ち」とし、DOM検査だけで視覚審査を合格にしません。

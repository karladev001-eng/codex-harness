# 平均時間の差を読み、実運用で確かめる

Deck: batch-comparison / revision: r3

## 1. S01 — 同じPC・各3回の演習用仮想値で比較する

### S01-P01

バッチ処理はデータをまとめて処理することです。今日は現行と改善案を同じPCで各3回測った設定で比べます。値は演習用の仮想値で、実際の測定結果ではありません。比較の前提を共有してから、平均時間の差を見ます。

出典: brief, measurements

つなぎ: 条件をそろえて、次に平均時間を見ます。

## 2. S02 — 演習の平均時間は15秒短縮

### S02-P01

現行は40、42、38秒で、3回の算術平均が40秒です。改善案は25、24、26秒で、平均25秒です。平均の差は15秒。現行の40秒を分母にすると37.5パーセント短縮です。横棒はどちらも0秒を起点とする同じ尺度です。各回の範囲は現行38から42秒、改善案24から26秒で、元データはレビューの出典から確認できます。ここでは演習値の差だけを読みます。

出典: measurements, summary

つなぎ: この演習の差が示せる範囲を確認します。

## 3. S04 — 実運用の短縮効果は未検証

### S04-P01

今回の値は演習用です。実運用の入力データ量と、どこからどこまでの時間を測るかは指定されていません。そのため本番でも15秒短くなる、あるいは37.5パーセント短縮するとは判断できません。演習値の差と実運用の効果を区別します。

出典: brief, next-proposal

つなぎ: 効果を確かめるため、実測条件をそろえます。

## 4. S03 — 入力量・測定範囲をそろえて実測する

### S03-P01

次の提案は、同じ入力データ量を用意し、開始と終了の測定範囲をそろえて実測することです。複数回の値を記録し、平均だけでなくばらつきも確認します。担当者と期間はまだ決まっていません。今日は実測でそろえる条件を合意し、次の作業で担当者と期間を決めましょう。

出典: next-proposal

つなぎ: この比較を共通の土台として、実測の条件を相談します。

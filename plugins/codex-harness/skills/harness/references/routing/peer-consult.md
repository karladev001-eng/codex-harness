# 別系統のモデルへの発案・助言・批評

相談相手は、実行中のホストとは別の系統のモデルです。Codexが親ならClaudeに[consult-claude](../../consult-claude/SKILL.md)で、Claude Codeが親ならCodexに[consult-codex](../../consult-codex/SKILL.md)で相談します。相手に回すかどうかは `status` の `collaboration.tasks.advice` で決まり、`off` なら自動では相談しません。

activeな親でdelegation ON、外部相談の停止指定がなければ、次のうち該当1役だけを使います。全役を一律には起動しません。inactive・delegation OFF・workerは自動起動しない。利用者が相手のモデルを名指しした明示依頼は別扱いとし、上位/ユーザー指示と割当範囲を守ります。

- `ideator`：企画・新用途・改善などの開かれた問いで、複数の視点が役立つとき。初回は親の案を渡さず、独立に発案させます。
- `consultant`：有力案の間で方針や優先順位に懸念があるとき、移行・認証/権限・公開API互換性などの重要な設計判断、または同じ問題を2回修正しても原因の見立てが更新できない停滞。
- `critic`：重要な提案・設計を確定する前の弱点確認と、明示的な批評依頼。独立コードレビューの代わりにはしません（コードレビューは各相談スキルの `reviewer` と `collaboration.code_review` で扱い、どちらが親でも同じ2者レビューです）。

単純な言い換え・定型変更・原因と対処が明確な修正では、通常は相談しません。外部の担当も同時実行枠に数え、空きを待ちます。既存のログインとツールなしCLIを使い、入力は最小限にします。通常1回、親が前回結果を明示する追加質問1回まで。再帰委譲・無限再試行は禁止です。親が自分の案と比べ、採否・理由・不確実性を統合します。回答を証拠・実行権限・ユーザー承認としない。

ログインを確認できないときは、未ログインと断定せず、各相談スキルの確認手順（consult-claudeは[認証確認と実行権限](../../consult-claude/SKILL.md#認証確認と実行権限)、consult-codexは `--check`）を先に行います。CLIが未導入・非対応か、その手順でも確認できない場合は制約を報告し、できる作業を続けます。相手への送信は、送る前に各相談スキルの `--approval` でプロジェクトと目的（purpose）の承認を判定し、`approved` なら聞き直しません。それ以外は1回だけ確認し、承認がなければ相談しません。persistence OFFでは、入出力・相談記録を永続保存しません。

案・資料・コード・テストの食い違いは論点を分け、元ファイル/原文/公式一次資料/実測の版・日時・条件へ戻る。重要矛盾が解消するまでは断定せず、未確定と報告します。多数決や相手との合意、追加相談で原情報の確認を代替しない。

# 調整手順

コード変更では、開始時と完了時に[技術的な修正の再利用・記録](../technical-lessons.md)を行います。freshなlessonを必要なときに少数だけ照合し、根拠のある修正だけを記録します。調査を委譲するだけなら、この追加手順は要りません。

1. **仕様とパケット**：[事前提示・承認](preimplementation.md#実装前の説明仕様視覚モック)を満たし、目的・対象外・番号付き受入条件を確定します。HTML計画スキルが使えれば、仕様の正本に対応する対話型HTMLを作ります（場所はソースcheckoutなら `authoring-skills/codex-html-plan/SKILL.md`、導入済みならこのスキルと同じ階層の同じパス、独立導入なら `.agents/skills/codex-html-plan/SKILL.md`）。スキルがなくても、提示・仕様・UIモックの要件は残ります。[パケット雛形](../../assets/task.md)に、担当範囲・依存・仕様版・コミット済みの基点・資料・未解決事項を書きます。探索は大きい場合だけ委譲します。文献探索は[探索](../roles/paper-discovery.md)で範囲と停止条件を分け、候補の確認は[資料確認](../roles/source-verification.md)に回します。親がIDの重複を除き、発見数と検証数を別に集計します。
2. **記録**：保存ONなら、必要な記録だけを `docs/harness/` に置きます。主要な入口と検証方法は[案内](../../assets/project-map.md)、あとに影響する判断は[ADR](../../assets/adr.md)に書きます。全ファイル一覧や会話全文は作りません。
3. **並列**：依存の欠落や循環を解消し、readyのタスクだけを並列に実行します。実装・制作では、提示・承認・必須判断がそろっているかを確かめます。準備としての調査・仕様・モックは妨げません。実装・調査・レビュー・統合・外部相談を合わせた同時実行数は、`max_agents`（既定3）とホスト上限の小さい方以下にし、[並列規則](../parallel.md)を守ります。
4. **モデル**：[役割・モデル](../roles.md)に従い、作業の性質からモデルを、必要な品質からeffortを別々に選びます。メインのモデルはホストの現在値で、変更できません。開始時と子を起動するたびに、実効設定・pinの由来・明示指定と、実際の起動面にある候補と対応effortを確認し、取得元・選択の根拠・実際のmodelとeffortを記録します（保存OFFなら会話内）。子は履歴なし方式で起動します（Codexは `fork_turns="none"`、Claude Codeは役割を指定した通常起動。[ホスト別](../hosts/codex.md)）。使えなければ報告し、別のモデルや全履歴へ黙って代替しない。
5. **引継ぎ**：子には `HARNESS_WORKER`、役割、パケット、役割参照の絶対パス、作業ディレクトリ、実効設定、必要な資料だけを渡します。未コミットのパケットは子worktreeにないので、インラインで渡すか親checkoutの絶対パスを示します。実効設定は親から渡し、子に基点で再解決させません。インラインでも、受入条件、資料の参照・版・提示証拠、承認範囲とユーザー発言根拠は省略せず、子は受け取ったときに確認します。別のタスクには新しい子を使い、同じ修正なら同じ子を続けてよいです。子の再委譲は禁止です。
6. **レビュー**：review ONなら、実装者と別の担当に[独立レビュー](../reviewer.md)を任せ、実差分・コードを読ませます。コードには[コードレビュー](../roles/code-review.md)を、Web画面の受入条件があってブラウザが使える場合は[画面評価](../roles/web-review.md)も適用します。修正と再レビューは最大2巡です。それでも残れば、親が仕様や方針を判断し、完了にしない。
7. **統合**：承認済みの変更は統合担当に渡し、依存順に統合して結合検証させます。review ONなら、最終的な変更間の整合性も独立レビューにかけます。親は統合コードを代筆しない（delegation OFFを除く）。
8. **完了**：修正記録の有無と理由、保存した場合はok・終了コード・pending・freshnessを確認し、未保存・未送信を完了扱いしない。最新の仕様・コードの版で受入条件と必要なレビューのPASSを確かめ、結果・変更パス・検証の証拠・未解決事項・commit IDを返します。仕様を改訂したら、影響を受けた結果と依存の統合を再検証します。

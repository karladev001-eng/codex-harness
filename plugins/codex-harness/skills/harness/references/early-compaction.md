# 早期compact

activeな長期作業で、上限前に引継ぎを整えホストの正式機能を使う運用。上位/ユーザー指示・権限・既存承認を守る。inactiveには適用しない。独自の背景監視・compact API・会話削除、勝手な設定変更を許可しない。

## いつ行うか

フェーズ境界・大量読取前にホストの現在コンテキスト量/現在有効なモデル上限を取得できれば確認する。アカウント枠・累計トークン・一般上限で代用しない。60%以上なら引継ぎを準備し、次の安全な区切りで大規模探索/新フェーズの前にcompactする。60%は運用目安で、公式閾値・推奨値・最適値ではない。固定トークン設定が全モデルで60%になるとも扱わない。

現在値/有効上限が不明なら推測しない。長い探索/大量ログのフェーズ終了時に蓄積情報と継続作業から判断する。短い作業・完了報告だけなら不要。安全な区切りまで進め、稼働処理・担当を無断停止しない。

## 実行前の引継ぎ

目的、最新指示/制約、仕様版・承認範囲/根拠、完了/未完、重要判断/根拠、変更パス/検証、稼働処理/担当ID、次の一手、失えない正確な値/参照を更新する。会話全文・生ログは複製しない。

保存ONは既存タスクパケット（`docs/harness/tasks/<id>.md` / 既存CLIの `<id>.json`）を正本とし、適切な記録がない場合だけ同領域に最小引継ぎを作る。保存OFFは同内容を会話内に置き、ファイル・永続記憶へ書かない。

## compactと再開

ホスト本体の正式な自動compactは別設定で動く。agent用実行toolがないことから、本体の自動機能もないと断定しない。このチャット用の正式実行機能がagentに提供されれば使う。別CLI・要約出力だけではこのチャットのcompactではない。実行機能がなければ引継ぎを整え、手動compactを一度だけ案内する。案内を繰返さず、強制せず、短く継続し参照を整理する。

実行記録には案内・実行・失敗/未実行と、手動/自動を判断した根拠を記す。イベントだけで自動実行と断定しない。使用量取得・正式実行・自動発火を保証せず、失敗/未実行を完了と記録しない。

復帰時は引継ぎと実状態を照合し、目的と未完了作業を続ける。compactは完了でも承認失効でもない。実質的な情報増加がなければ60%以上でも連続実行せず、短い継続と参照整理で対応する。未完了確認までタスクを完了にしない。

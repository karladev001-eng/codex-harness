# 早期compact

activeな長期作業で、上限に達する前に引継ぎを整え、ホストの正式な機能を使うための運用です。上位指示、ユーザー指示、権限、既存の承認を守ります。inactiveには適用しません。独自の背景監視・compact API・会話削除や、勝手な設定変更は許可しない。

## いつ行うか

フェーズの境目や大量の読取の前に、ホストの現在コンテキスト量と現在有効なモデル上限を取得できれば、確認します。アカウントの枠、累計トークン、一般的な上限で代用しない。60%以上なら引継ぎを準備し、次の安全な区切りで、大規模な探索や新しいフェーズに入る前にcompactします。60%は運用上の目安で、公式の閾値、推奨値、最適値ではありません。固定のトークン設定が、すべてのモデルで60%になるものとも扱わない。

現在値や有効な上限が不明なら、推測しない。その場合は、長い探索や大量のログを扱ったフェーズの終わりに、蓄積した情報と続ける作業から判断します。短い作業や、完了報告だけの場合は不要です。安全な区切りまで進め、稼働中の処理や担当を無断で停止しない。

## 実行前の引継ぎ

次を更新します。目的、最新の指示と制約、仕様版・承認範囲と根拠、完了した作業と未完の作業、重要な判断とその根拠、変更したパスと検証、稼働中の処理と担当ID、次の一手、失えない正確な値と参照。会話全文や生ログは複製しない。

保存ONなら、既存のタスクパケット（`docs/harness/tasks/<id>.md`、既存CLIでは `<id>.json`）を正本とし、適切な記録がない場合だけ、同じ領域に最小限の引継ぎを作ります。保存OFFなら、同じ内容を会話内に置き、ファイルにも永続記憶にも書かない。

## compactと再開

ホスト本体の正式な自動compactは、別の設定で動きます。agent用の実行toolがないことから、本体の自動機能もないと断定しない。このチャット用の正式な実行機能がagentに提供されていれば、それを使います。別のCLIや要約の出力だけでは、このチャットのcompactにはなりません。実行機能がなければ、引継ぎを整えたうえで、手動compactを一度だけ案内します。案内は繰り返さず、強制もせず、短く作業を続けながら参照を整理します。

実行記録には、案内した、実行した、失敗した、実行しなかった、のいずれかと、手動か自動かを判断した根拠を記します。イベントだけで自動実行と断定しない。使用量の取得、正式な実行、自動での発火は保証せず、失敗や未実行を完了と記録しない。

復帰したときは、引継ぎと実際の状態を照合し、目的と未完了の作業を続けます。compactは、完了でも承認の失効でもありません。実質的な情報の増加がなければ、60%以上でも連続して実行せず、短く作業を続けて参照を整理することで対応します。未完了の確認が済むまで、タスクを完了にしない。

# 正本・関連記録・保存と開き方

## 既存記録を確認する

プロジェクトの文書入口、命名、保存先、関連リンク欄と作成規約を読む。ADR/EXP/LOG/TASKという名前だけで用途を推定しない。今回の仕様に対応する記録だけを選ぶ。例えばTASKが仕様正本、ADRが決定、EXPが検証、LOGが経緯というプロジェクトならその役割を使う。存在しない文書種類を一律生成しない。新しい判断や実験の記録が必要なときだけ規約に沿って作る。

仕様本文は正本に集約し、関連記録へ重複コピーしない。HTMLに「関連ドキュメント」欄を設け、正本と選んだ記録のID・種別・今回の役割・HTMLからの相対リンクを書く。各関連記録の既存リンク欄には正本/HTMLへの逆参照を置く。承認状態と根拠の正本は一箇所にする。文書の存在は実装承認や実験成功の証拠ではない。

## 正本のMarkdown

通常は既存TASKと同じフォルダに `<id>.plan.html` を置く。Markdownに以下を記す。

- 計画ID、仕様版、承認対象範囲、HTMLへの相対リンク。
- HTMLを開くコマンド、その実行ディレクトリ、OS/シェル。
- 関連記録のIDと今回の役割。

JSONのみが正本ならschemaへ未知のキーを追加しない。既存Markdown/索引へ参照と開き方を書く。

例（macOS・zsh、実行ディレクトリ `/work/project`）:

```sh
open "docs/tasks/TASK-42.plan.html"
```

Linuxは利用可能な `xdg-open "docs/tasks/TASK-42.plan.html"`、Windows PowerShellは `Start-Process ".\docs\tasks\TASK-42.plan.html"` を使える。絶対パスで渡す場合も、空白を含むパスを引用する。コマンドの記載だけで起動や外部公開を実行する許可とは扱わない。

HTMLは単独でオフライン表示できるが、関連Markdownは別ファイルのまま。共有するときは相対配置を保つか、リンク先が同梱されないと示す。HTTPプレビューでは関連ファイルに到達できる配信ルート/URLを選ぶ。ローカル配信は必要時だけで、外部公開はこのスキルの範囲外。

## 改訂と保存OFF

計画ID/仕様版を変える場合は正本とHTMLを同期する。移動・改名した場合は双方の相対リンク、起動コマンド、実行ディレクトリを更新し、リンク先実在と版対応を確かめる。重要変更は過去承認を流用せず再承認する。

保存OFFでは正本を会話に残し、永続記録を新規作成/追記しない。表示用HTMLは一時フォルダに作り `data-persistence="off"` を使う。会話内に計画ID/版/範囲、既存記録への参照、絶対パスのHTMLリンク、起動コマンドと実行ディレクトリを示す。runtimeはlocalStorageを読まず書かない。再表示に備える永続記憶へファイルを保存しない。

## packの境界

`pack.mjs` は入力HTMLのフォルダ、runtimeフォルダ、明示した `--root` のrealpath配下だけを読む。symlinkで外へ出る参照や既知のsecret名は拒否し、コードのsecretらしい内容を検知する。Git参照は許可されたplumbingだけを使う。コードや画像の読取失敗で不完全な成果物を完成と報告しない。埋め込むコードは共有可能な内容か確認する。

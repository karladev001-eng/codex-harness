# 仕様書の固定配色

## 適用条件

codex-html-planで仕様・設計・確認用HTMLを新規作成または修正するときに適用する。文書外枠・概要・カード・表・補足・リンク・回答/承認操作を対象にする。製品モックの配色・本文フォントは依頼なしに変更しない。

## 手順

- `runtime/htmlplan.css`の共通トークンを使う。文書は常時lightとし、OSの明暗や`data-theme="dark"`によって反転させない。
- 背景は`--paper: #f8fafc`、カードは`--card: #ffffff`、沈み面は`--sunk: #eef2f6`。本文は`--ink: #172033`、補足は`--ink-2: #334155` / `--ink-3: #475569`、リンクは`--accent: #1d4ed8`を使う。
- 局所CSSで背景を指定する場合は文字色も同じ規則で対に指定する。文字色の継承だけに頼らない。独立した暗背景の端末・引用・製品モックも背景と文字を対にし、文書トークンでその内容を上書きしない。
- 相対輝度によるコントラストを計算し、本文は7以上、補足・リンク・状態表示は4.5以上を内部基準とする。薄い状態背景、hover、無効・削除状態、opacity適用後も点検する。色だけで状態を区別せずラベルや形を併用する。
- 元HTMLと配布サンプルをpackし、OS明暗・既存theme指定・狭幅で確認する。ブラウザが使えない場合は静的検証と表示未確認を区別し、別経路で制約を迂回しない。

## 記録契約

- 新規作成・配色変更時、対応する既存TASK/仕様正本へ対象、主要な前景/背景と実コントラスト、pack/表示確認の結果・未確認事項を記録する。保存OFFの場合はチャットの結果報告に残す。
- 再修正時は同じ記録を更新する。内容・計画ID・版・承認pending・回答identityは配色修正だけで変更しない。
- 必読リンクの解決、関連テスト、再pack、確認結果の記録が揃ったことを完了根拠とする。表示未確認を確認済みにしない。

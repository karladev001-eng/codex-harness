# 制作・通読・改訂

正本はdeck.json。story.md/script.mdは生成ビュー。TASK参照は`taskReference`に相対path・計画IDなどを置き、制作内容と承認記録を二重編集しない。既存プロジェクト形式を優先する場合は、同等の情報とID対応を保持してpack用JSONへ変換する。

初稿では目的、聞き手の前提、持ち時間、要旨、期待する理解/判断、章とページの役割を先に設計する。各ページに主要メッセージ、補足、話す要点、ノート、次へのつなぎ、秒数、出典を記す。スライド本文の短さと読み上げ原稿の全文を区別し、導入から結びまで自然な文章を作る。制作上の未解決事項はdeck.unresolvedに置き、発表用表示へ混ぜない。

Codexの通読チェックは次を実際に読む。`coherence.checks`の各行に確認項目、結果、確認根拠を書く。単なる定型のPASS一覧にしない。

- 聞き手の前提と用語初出。略語・単位・基準の説明があるか。
- 目的から結論までの論理、飛躍、重複、矛盾。結論が根拠の射程を超えていないか。
- ページ間の自然さ。前ページの最後と次ページの冒頭を続けて読む。
- 図表・ラベル・原稿の一致。原稿に追加した数値・事実のsource IDs。
- 推定時間と指定時間。文字数/速度の仮定と、実測リハーサルとの区別。

指摘は`id,slideId,paragraphId,quote,impact,reason,suggestion`。理解できるとの保証や実際の聞き手評価にしない。確認できなかった事項は`unchecked`へ残す。`pack.mjs hash deck.json`のcontentHashを、対象revision・確認者・日時と一緒にcoherenceへ入れる。hashはcoherence自体を除外するので、チェックの追記でhashが循環しない。内容が変わったら旧確認結果のhashは不一致となりpackは拒否する。新しい確認を終えてからhashを更新する。

出典は引用した範囲だけを記録する。Web直接URL/組織/日付/箇所/閲覧範囲/確認日、project相対path/実在行か見出し/hashまたはcommit、データの列/単位/期間/抽出条件、派生の入力IDs/式/コード/出力/母数/欠測を揃える。Web到達性は標準の閲覧ツールで確認し、packのオフライン検査と区別する。再計算していない記録値を現在の実測と言わない。仮値・概念図には明示ラベルを付ける。

図画像のasset registryには保存file、実在するoriginals、形式、生成/取得元、利用slide IDs/source IDs、再生成手順、利用条件を残す。生成画像は生成素材と明記する。原本/編集用データがなければ不存在を伝え、架空の原本を作らない。全プロジェクトのコピーはしない。秘密・認証情報を含む素材を選択しない。

初期のstoryとlayoutは独立して選ぶ。カタログの量・適否・必要素材を確認し、型に合わせるために聞き手に不要なスライドを増やさない。独自layoutは情報の優先順位と関係からgrid/canvasを設計し、独自ID・版・適用条件・調整可能箇所を記録する。プロジェクト内のdeck.catalogまたはプロジェクト保存規約へ保存する。共有catalogや元masterを自動上書きしない。同じslide/element/source IDを案A/Bに配置する。

生成物はrevision全体の新規ディレクトリで、衝突を拒否する。再生成が必要ならrevisionを上げる。正本・素材原本や既存出力を削除して上書きしない。案別コメントはdeck/revision/variant/contentHashで分離され、保存OFFではlocalStorageを読書きしない。ONはユーザーの選択時だけ。読込した別版JSONは画面に適用されない。

チャットでコメントを受け取ったらJSONがあれば`feedback-check`で照合する。表セル/系列の元データ参照、原稿段落、当時のページ番号、原文引用を確認する。並べ替えはslide IDを維持する。削除された要素は未対応と示す。新しいrevisionに変更を反映し、関連図表/出典/原稿/つなぎ/通読チェックを更新して生成・再提示する。HTMLを直接編集して正本へ無言で逆同期しない。
